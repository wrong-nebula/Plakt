# Native studio polish

Applied the [Emil Kowalski design-engineering skill](https://emilkowal.ski/skill) to the SwiftUI app. The installed `emil-design-eng` skill informed interaction frequency, immediate feedback, purposeful motion and visual consistency. Native macOS controls provide press, focus, hover and menu behavior.

| Before | After | Why |
| --- | --- | --- |
| Review opened a separate HTML page | Generate and Review library workspaces inside the main window | Keep source correction next to generation |
| Dense review toolbar competing with the image | Smaller, grouped library controls and a stable footer | Give the artwork the main visual area |
| Click four points from scratch | Numbered draggable handles, zoom, arrow-key nudges and optional coordinate fields | Support accurate correction with several input methods |
| Switching a poster discarded unsaved points | Per-library border drafts saved locally | Preserve work during browsing |
| All instructions and coordinate fields stayed expanded | Short guidance with a coordinate disclosure | Keep the common operation clear |
| Element selection through a long dropdown | Clickable region boxes plus optional word boxes | Inspect the element directly |
| Five fixed equal ballots | Fourteen style families, sixteen craft/image checks and 27 designer-affinity profiles in grouped disclosures | Make judging preferences visible and adjustable |
| Designer names without source context | Per-profile reference links, model basis and held-out ranking metrics | Make the evidence behind a vote inspectable |
| A designer preset changed only ranking | Authored generation neighborhoods plus the chosen real-work affinity vote | Produce useful variation while stating how the preset works |
| Recipe-based style labels had no review workflow | Explicit present/absent/unknown source labels and local retraining | Build a dataset without treating unknown labels as negatives |
| Border selection moved behind animation | Direct pointer tracking and immediate keyboard nudges | Precision tools must stay attached to input |
| Final automatic winner hid an earlier strong result | Saved Curator pick opens its actual direction, round and candidate | Preserve visual selection separately from committee ranking |
| Source-study iteration hid rejected duplicates | Show the resampled proposal count next to ancestry | Make the search process inspectable |
| More style directions cramped a segmented picker | Direction menu for larger studies, segmented control for small ones | Keep fourteen choices readable |
| Only one curated result could be opened | Compact Curator picks menu with three distinct directions | Browse the kept results without hiding the other studies |
| Source breeding ignored shared copy and seed controls | Snapshot and validate the entered copy, seed and candidate count | Make the controls describe the actual run |
| Recent study disappeared after reopening | Restore the last opened study | Make returning to work predictable |

No decorative page transitions or staggered gallery entrances were added. Frequent selection, search and keyboard operations stay immediate. Native progress indicators signal ongoing work without shifting the footer. UI colors use adaptive system surfaces and a single accent; source artwork retains its own measured palette.

| Before | After | Why |
| --- | --- | --- |
| A committee of predefined style/craft judges | Taste check in the main header, with independent weighted preference profiles | Let the user form a personal jury from actual output choices |
| No explicit personal examples | Yes/no/skip deck, saved favourites, vote history and undo | Capture preference without inventing negative labels |
| Every retained elite could repeat in training | Exact-image deduplication and preserved source-layout groups | Reduce repeated examples and split related layouts together |
| Hidden readiness/confidence | Label counts, three-per-class threshold and conditional held-out agreement | Show when a personal juror can vote and when its evidence is still small |
| Preferences could change during a study | Frozen checksum-bound model snapshots per run | Keep comparisons consistent while the user continues voting |
